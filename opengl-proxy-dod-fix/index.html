Darkest of Days: black screen on modern AMD GPUs

The menu works, the level loads, the audio plays, and the screen stays black. The cause is one piece of OpenGL state that AMD's driver forgets to restore. A small proxy opengl32.dll restores it, without touching the game.

symptom black screen with audio as soon as a level starts
affects AMD GCN and newer (tested: RX 7900 XTX, driver 32.0.31041.1004)
cause glPopAttrib leaves GL_DEPTH_BOUNDS_TEST_EXT switched on
fix drop opengl32.dll next to darkestofdays.exe

↓ download opengl32.dll source on GitHub

[1] the bug

When a level starts, the game draws a lighting pass inside a save/restore pair:

glPushAttrib(GL_POLYGON_BIT | GL_ENABLE_BIT | GL_SCISSOR_BIT);
glEnable(GL_DEPTH_BOUNDS_TEST_EXT);
glDepthBoundsEXT(0.99944, 0.99948);
... draw ...
glPopAttrib();   // must switch the depth bounds test off again

The EXT_depth_bounds_test spec puts the enable flag in the GL_ENABLE_BIT group, so the pop has to turn the test off. Here is the depth bounds test state after each call, on a driver that follows the spec and on AMD's current driver:

  1. callspecAMD
  2. glPushAttrib(… GL_ENABLE_BIT …) off, saved off, saved
  3. glEnable(GL_DEPTH_BOUNDS_TEST_EXT) on on
  4. glDepthBoundsEXT(0.99944, 0.99948) on, tiny range on, tiny range
  5. draw lighting pass drawn drawn
  6. glPopAttrib() off, restored still on
  7. every later draw drawn rejected
  8. result level renders black screen

Why everything gets rejected

The depth bounds test doesn't look at the new fragment. It looks at the depth already stored in the depth buffer, and throws the fragment away if that value lies outside the range. After a clear, every pixel stores 1.0, which sits just outside the range the game left behind:

So the colour pass, the depth pre-pass and everything after them are discarded for the rest of the level. Even the depth pre-pass can't write a new depth, which is why the buffer stays at 1.0 forever. The older TeraScale driver (HD 2000 to HD 6000) restored the state correctly, which is why the game used to work.

How it was tracked down
  1. An apitrace capture of the black screen replays black on the same card, so the problem is in the GL call stream, not timing or the game's own logic.
  2. All shaders compile and link, and state dumps around draws look sane.
  3. The depth buffer stays at 1.0 even after the colour-masked depth pre-pass, so fragments are being rejected before they can write depth.
  4. Bisecting the GL state shows GL_DEPTH_BOUNDS_TEST_EXT still enabled after the matching glPopAttrib.
  5. A standalone 30-line push, enable, pop test reproduces it on the driver for GL_ENABLE_BIT, GL_DEPTH_BUFFER_BIT and GL_ALL_ATTRIB_BITS. The bug has been reported to AMD.

[2] the fix

Windows looks for DLLs in the game's folder before System32, so a file named opengl32.dll next to the exe gets loaded in place of the real one. The proxy forwards every call to the real opengl32.dll and wraps only four of them:

game darkestofdays.exe unmodified
every GL call
proxy, game folder opengl32.dll 364 exports: jump straight through 4 wrapped: glPushAttrib, glPopAttrib, glNewList, glEndList
forwarded
System32 opengl32.dll → AMD driver

What the wrappers do

  1. glPushAttrib(mask)
  2. Does mask include GL_ENABLE_BIT or GL_DEPTH_BUFFER_BIT?
  3. If so, read whether the depth bounds test is on, and the range when the depth bit is set.
  4. Push that onto a shadow stack.
  5. Call the real glPushAttrib.
  1. glPopAttrib()
  2. Call the real glPopAttrib.
  3. Pop the shadow stack.
  4. Put the range back if it was saved.
  5. Switch the test on or off to match what was saved. This is the line AMD's driver skips.
  • glNewList/glEndList are watched so pushes compiled into display lists don't desync the shadow stack.
  • Pushes past the driver's stack limit are ignored, the same way the driver ignores them.
  • Without GL_EXT_depth_bounds_test the proxy just forwards everything.
  • If a future driver fixes glPopAttrib, the proxy restores what is already correct, so it can stay installed as a no-op.
  • Set DOD_GLFIX_REAL_OPENGL32 to chain it in front of another wrapper such as apitrace.

[3] install

  1. Download opengl32.dll, or build it from glfix/ with MinGW-w64 (the game is 32-bit, so the DLL must be too).
  2. Copy it next to darkestofdays.exe.
  3. Play. dod_glfix.log appears next to the exe to confirm the fix is active.

To uninstall, delete opengl32.dll from the game folder.

# build on Linux (or MSYS2: mingw-w64-i686-gcc)
sudo apt install gcc-mingw-w64-i686
glfix/build.sh   # -> glfix/build/opengl32.dll
